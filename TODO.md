#### Live GUI preview migration

Confirmed contract: extend test-only `test.h` with caller-owned `test_command_live`, `test_command_start(live, workspace, command)`, `test_command_poll(live)` and `test_command_finish(live)`. User selected caller-driven polling over background supervision. No worker thread, watchdog, scheduler or application `process_run` change.

```c
test_command_live viewer = {0}, inspector = {0};
test_command_start(&viewer, &viewer_workspace, &viewer_command);
/* Poll viewer until project-local complete readiness event. */
test_command_start(&inspector, &inspector_workspace, &inspect_command);
/* Poll both until inspection completes; require viewer still alive. */
/* Validate inspection, then poll viewer through exit/capture EOF. */
test_command_finish(&inspector);
test_command_finish(&viewer); /* Cancel/reap on early return; idempotent. */
```

- Zero-initialize live state; never copy/move active state. Capture buffers stay separate, stable and exclusive through completion. Start borrows command/input/scratch only until return; scratch rewinds to entry mark immediately and may serve another start.
- Poll drains at most 16 KiB per stream and checks monotonic deadline from start. All live children must be polled; blocking caller work delays deadline enforcement. Poll may perform bounded terminal cleanup. Existing OS-call and cleanup limits remain; no hard real-time guarantee.
- Normal completion preserves native exit/signal. Timeout, I/O/capacity failure and explicit cancellation remain distinct infrastructure results. Every terminal path releases owned handles/descriptors and Windows job/POSIX group; cleanup failure remains visible. Finish cancels active child, is harmless on unused state and returns existing result after completion.
- User retained documented Windows job-drain contract: wait direct child and verify job active count zero. Job-empty does not guarantee every descendant process object is already signaled. Known-descendant tests use bounded 1000 ms native handle waits, then heartbeat checks; no padding sleep/retry or new process-tracking manager.
- `test_command_run` wraps same lifecycle; preserve existing finite byte stdin, argv/cwd/environment, captures, validation and ownership guarantees.
- Readiness, JSON, cross-compiler inspection, feedback and fixture policy stay project-local. Poll viewer and inspector together; no sleeps in place of readiness. Case teardown finishes both before retaining/removing owned fixtures. Preserve actual inspection while viewer is alive, Unicode-code-point context/range checks, saved bytes/hash, unchanged prior files, owned context and explicit resolution/body preservation.
