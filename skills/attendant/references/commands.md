# Record and query commands

All commands accept `--project` / `-p`. Successful output is JSON. `@path` reads UTF-8 input; `-` reads stdin once where text input is accepted.

## Create

```sh
node <skill-dir>/scripts/attendant.mjs create -c tasks -i @items.json
```

`--collection`/`-c` and `--items`/`-i` are required. Items is a non-empty JSON array of `{ "name": "...", "fields": { ... } }` objects; `fields` defaults to `{}`. Use the same array shape for one or many records. The runner validates every item and checks all target paths before creating any record; its output has a `records` array. Fields must be declared in the collection schema, except built-in writable metadata: `desc` (string) and `tags` (string array). `id`, `name`, and `created_at` are generated by the runner.

## Update

```sh
node <skill-dir>/scripts/attendant.mjs update -c tasks -i @updates.json
```

`--collection`/`-c` and `--items`/`-i` are required. Items is a non-empty JSON array of `{ "name": "...", "fields": { ... } }`; use the same array shape for one or many updates. Attendant accepts only declared collection fields plus `desc` and `tags`; it rejects immutable fields including `id`, `name`, and `created_at`. Every target and merged record is validated before any source file is replaced. Each replacement is atomic, but a batch is not a cross-file transaction. Record bodies are preserved and the projection is reconciled afterward.

## Validate and sync

```sh
node <skill-dir>/scripts/attendant.mjs validate [--no-correct|--strict]
node <skill-dir>/scripts/attendant.mjs sync
```

Validation applies only mechanical corrections by default. `--no-correct` reports without source changes; `--strict` also exits non-zero for diagnostics or pending corrections. Sync rebuilds generated projection from source.

## Inspect and query

```sh
node <skill-dir>/scripts/attendant.mjs schema
node <skill-dir>/scripts/attendant.mjs query -s "SELECT 'tasks' AS collection, id, name FROM tasks WHERE status = :status" -P '{"status":"todo"}' -l 20
node <skill-dir>/scripts/attendant.mjs search -q 'SQLite projection' -c tasks,decisions -l 20
node <skill-dir>/scripts/attendant.mjs doctor
```

`query` requires `--sql`/`-s`; `--params`/`-P` defaults to `{}` and must be a JSON object. Before writing a query, read the target collection's `.schema.md` or inspect `schema`; only use its declared fields and documented built-ins. Do not assume fields such as `priority` exist because another project or template uses them. In Bash, do not add backslashes to JSON already enclosed in single quotes; prefer `-P @params.json` for generated or complex values. `search` requires `--query`/`-q`; `--collections`/`-c` is comma-separated. `--limit`/`-l` is a non-negative integer and defaults to 100. Include collection identity as a SQL literal because it is not a projected column. `doctor` is read-only health diagnosis, not routine follow-up.
