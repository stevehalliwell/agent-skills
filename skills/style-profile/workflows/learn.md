# Style learner

Create evidence-based style profiles without claiming exact voice replication.

## Required read

Read `../references/style-profiles.md` before work. Done when profile format, provenance, and profile-path rules are known.

## Workflow

1. Gather profile name, intended use, exemplar sources, target genres, and save scope/path when user wants file output. If a target draft already exists, record its form (notes, outline, rough prose, or finished prose) and the intended transformation. Done when profile purpose, target use, and output mode are known.
2. Record each source path or URL, origin/permission note, genre, approximate word count, claim limits, and any conversion/import artefacts. Require at least 1,000 words and three representative excerpts by default. If corpus lacks either, request more material or explicit provisional-profile approval. Do not infer author identity, permission, or claims. Done when corpus sufficiency and provenance are known.
3. Group the corpus into meaningful modes before deriving rules: genre, period, subject matter, source format, and degree of polish where observable. Identify the closest mode for each intended use. Do not flatten conflicting modes into a single average; record a variation or open question instead. Done when the profile says which evidence governs which target.
4. Confirm permission before reproducing third-party excerpts. With no user-provided reuse permission, analyse source without quoting it; request approved excerpts if profile needs representative excerpts. Done when every reproduced excerpt has permission or its absence is an explicit limitation.
5. Extract observed voice, vocabulary, sentences, composition, structure, punctuation, deterministic evidence-backed anti-patterns, and descriptive metrics. Capture how writers open, move between points, develop a point, qualify a judgement, use standalone labels, and end; these mechanics are more actionable than tone labels alone. For local Markdown corpora, include the documented `Verification calibration` section in the profile. Use its standalone-label maximum words setting when running `../references/style-profile-metrics.mjs --paragraph-label-max-words <setting> --output <profile-path-without-.md>.metrics.json <Markdown files...>`, then record its output as descriptive evidence; otherwise mark metrics unavailable. The sidecar must retain one corpus-level `metrics` summary with statistical summaries, per-document comparison distributions, standalone-label tracking, paragraph progression summaries, POS word-type percentages, vocabulary counts, and bounded common/rare word lists, but never source text, paths, raw arrays, per-document results, or a complete word-frequency table. Separate `Observed`, `Interpretation`, and `Open questions` wherever evidence is weak. Done when each rule has corpus support or an explicit uncertainty label.
6. Turn observations into bounded generation guidance: name the target mode, 1–2 calibration excerpts, composition moves to preserve, and failure modes to avoid. State what must remain source-led when expanding notes, such as uncertainty, repetitions that carry emphasis, point order, and the distinction between fact, judgement, and future intent. Do not turn descriptive metrics into quotas. Done when another agent can select an anchor and draft without reducing the style to generic polished prose.
7. Choose 3–5 permitted, representative 50–150 word excerpts. Prefer ordinary work; avoid boilerplate, unusual formatting, large quotes, code unless target style needs code. Cover rhythm, vocabulary, tone, structure, and composition; label which target mode each excerpt calibrates. Done when excerpts meet range, provenance, permission, coverage, and mode requirements.
8. Validate profile: three excerpts, source/provenance and target mode each; observed rules across voice/vocabulary/sentences/composition/structure/punctuation; actionable generation guidance; deterministic anti-patterns only with evidence; and a complete, non-negative Verification calibration section. When a sidecar exists, confirm its standalone-label maximum matches the profile before saving. Compare a short unseen sample qualitatively when one is available; mark rules needing confirmation. Done when validation passes or limitations are explicit.
9. For file output, write the confirmed `.pi/style-profiles/<name>.md` or `~/.pi/style-profiles/<name>.md` and its same-named `.metrics.json` sidecar. The Markdown profile links to the sidecar and keeps only human-readable metric interpretation; chat output writes nothing. Done when profile and sidecar are returned or saved.
10. When the profile has a saved sidecar and locally accessible corpus items, ask: `Would you like a corpus outlier review? It will use the verify workflow to compare every item statistically and qualitatively against the new profile, then rank them by statistical deviance.` If accepted, run the verify workflow in corpus-review mode with the profile and original corpus paths. Return its ranked table, then identify which items may warrant corpus exclusion, a separate mode, or manual review; do not change the corpus or profile without user approval. If declined or inputs are inaccessible, hand off to the generate workflow or the verify workflow. Done when review is offered and any accepted review is returned.

## Boundaries

- Do not create finished documents or rewrite exemplars.
- Do not copy third-party excerpts without user-provided reuse permission.
