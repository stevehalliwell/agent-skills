# What this example exposes

These are concrete limits of the current representation or of this unfinished design, not automatic requests for new tooling. Keep existing 15 collection owners; no parallel design database. Use ordinary source reading when a deterministic consumer cannot answer a question.

## Structured proposals are not a gameplay runtime

[Growth supplies](game-design/mechanics/supply-release.md) depend on form at release; a [small hero collecting an existing flower](game-design/interactions/touch-flower-small.md) depends on a later state. All interaction/mechanic records now have readable participant-scoped rule blocks. Native `rules --case` evaluates supplied hypotheses, explicit mapped calls and simultaneous proposals; `--analyze` compares bounded known enum branches. Matrix still uses flat pair links. Neither view executes gameplay, resolves event timing or proves exhaustive coverage.

Likewise, [pipe entrance](game-design/interactions/enter-open-pipe.md) needs an instance, alignment and input. The noun pipe does not identify which placed pipe is enterable. Geometry/instance identity is absent, not inferred from nouns. Conditional state proposals under supplied facts do not prove that an actual pipe can be reached or entered.

## Route opportunity is not conditional capability

[Flower shelf](game-design/challenges/flower-shelf.md) introduces shooting only if a reward is collected in the right form. Declaring introduces gives the current route analysis an opportunity; it cannot certify that every arrival gained spark power. Shell-lane therefore does not falsely require shooting.

Cellar bypass and staircase fork are explicit next links. Their optional choices have no encoded probabilities. All mandatory jump/landing prerequisites currently have earlier opportunities on every declared route; bypass alone is not a missing-support finding. [Finish-approach](game-design/skill-atoms/finish-approach.md) is first tested at final-gap without an earlier explicit introduction/practice: native analysis reports absent support. A designer may judge earlier component practice sufficient, refine the role declarations, or alter the course; the tool does not choose.

## Retry behavior cannot be reduced to ordinary next arrows

[Death-and-retry](game-design/mechanics/death-and-retry.md) changes lives, form, clock, world objects and anchor. Adding an unqualified back edge would mix forward route opportunities with stateful retry semantics. Current graph deliberately omits those retry edges. It does not calculate remaining lives, duplicate reward farming, checkpoint-conditioned histories or reachable power states.

## Flat field checks do not validate every design invariant

[Starting lives](game-design/control-vars/starting-lives.md) must not exceed [life capacity](game-design/control-vars/life-capacity.md); run target should exceed walk target for the intended distinction. Native controls enforce their documented types, formulas, units and individual bounds, not arbitrary prose inequalities across records. A successful export does not validate all game rules.

Resource [coin capacity](game-design/control-vars/coin-bank-capacity.md) describes stable state after conversion, not a collection clamp that prevents reaching the conversion threshold. Collection/conversion branches author final quantities from the same immutable starting values, not sequential writes. No general resource-flow graph is inferred. [Score](game-design/resources/run-score.md) has no authored capacity; an eventual implementation still needs safe machine bounds.

## Explicit unknowns are not broken references

[Standing under a ceiling](game-design/interactions/stand-under-low-ceiling.md) and [two-shell collision](game-design/interactions/shell-meets-shell.md) are unknown responses. [Remote finish activation](game-design/interactions/shoot-finish-post.md) is excluded. [Collecting camera state](game-design/interactions/collect-camera.md) is not applicable. Other cases explicitly define no effect. Keep these dispositions distinct; absence of an error does not make the case complete.

Growth with insufficient clearance, spark–shell contact, shell–walking-shellback contact and simultaneous expiry/finish remain explicit unmodeled/unknown outcomes, including cases within shared mechanic blocks. This shows that 49 cases are not an exhaustive Cartesian product.

## Evidence and geometry remain separate

Proposed dynamics/aesthetics and their links are not player observations, causal proof or a fun score. The three investigations have no results. [Travel-budget](game-design/experiments/travel-budget.md) is blocked on absent route lengths; do not replace them with challenge counts or invented delay probabilities.

No tile map, jump impulse, gravity, hitbox dimensions or measured path lengths exist. Challenge membership and authored ranks cannot establish physical reachability. The example is design data, not a reverse-engineering or game-execution tool.
