# Working memory and chunking

Pack: `working-memory` · version 1
Attribution: George A. Miller (1956); Nelson Cowan (2001, later reassessments)

## Scope

Explore what must be remembered, what is visible, and how familiarity might combine elements into learned chunks.

Use only when this lens is selected. Follow [review operation](../review.md); do not repair source during review.

## Inputs and query support

Roles: `skills`, `challenges`, `mechanics`, `observations`. Read actual role mapping and live schema/usage before writing.

Available recipes: `query skills`; `query routes`; `query records --collection <mapped-alias>`. These are declared-data projections, not automated framework verdicts. Inspect linked bodies for conditions and evidence.

## Original prompts

1. Which state must the player remember after it disappears from view?
2. Could a stable cue externalize that memory without solving the intended puzzle?
3. What appears to an expert as one familiar operation but to a beginner as several independent decisions?
4. Does a learned combination remain recognizable when presentation or context changes?
5. Which competing cues need attention together, and which can be processed in sequence?
6. What would compare a memory-support variant with the original while preserving the intended reasoning?

## Missing data and evidence limits

Unspecified visibility and familiarity remain unknown. Do not equate number of skills with number of active memory chunks.

Never use four, seven, or another item count as universal failure/capacity threshold. Chunk size depends on learning and task. No player-capacity dataset or computed memory score.
