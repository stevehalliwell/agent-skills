# systems

Group constructed rule arrangements. Systems are not emergent dynamics.

## Operating rules

- Read this usage and schema before record operations. Markdown is authoritative.
- Stable technical name is separate from mutable glossary terminology. Preserve id, name, created_at.
- Capture supplied non-tentative facts as accepted; generated alternatives remain proposed until designer adopts them.
- Lifecycle: proposed, accepted, rejected, superseded, defunct. Retain rejected/inactive records and supplied rationale; use Git for edit history.
- Unchosen siblings remain proposed. Review is not repair authorization.
- Empty optional fields preserve incomplete design. Missing/null/empty link arrays mean no declared links. Scalar null is not zero/false.
- Use qualified references and one authoritative definition. Bodies own prose; do not duplicate shared rules or tuning.
- Terms/aliases live only in glossary; compare case-insensitively after trim/collapse whitespace. Ask about undeclared synonyms; never guess collisions.
- Do not infer fun, learning, player capability, or observed behavior from link counts. Framework review requires an explicitly selected lens.
- Initial native C99 analysis/view/simulation capabilities are not installed in this release. Query helpers inspect declared data only.
