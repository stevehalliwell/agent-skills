# Resources, flows, and feedback

Pack: `resource-economy` · version 1
Attribution: Ernest Adams and Joris Dormans, Game Mechanics: Advanced Game Design (2012); Machinations approach

## Scope

Examine a selected resource and the rules that create, spend, transform, or limit it. Separate resource identity from adjustable quantities.

Use only when this lens is selected. Follow [review operation](../review.md); do not repair source during review.

## Inputs and query support

Roles: `nouns`, `resources`, `controls`, `mechanics`, `interactions`, `measures`, `expectations`, `experiments`. Read actual role mapping and live schema/usage before writing.

Available recipes: `query controls`; `query matrix`; `query records --collection <mapped-alias>`. These are declared-data projections, not automated framework verdicts. Inspect linked bodies for conditions and evidence.

## Original prompts

1. What is the resource, what stores it, and which rule changes it?
2. Which sources and sinks depend on player choices, elapsed time, or chance?
3. Does gaining more of this resource make future gains easier, harder, or neither? What intervening rule creates that feedback?
4. Which capacity or initial-value controls bound the state, and where are conversion assumptions written?
5. Could a proposed balance change produce different outcomes for different strategies rather than one new average?
6. What minimal measurement would test the disputed system claim, and which behavior assumptions would that model omit?

## Missing data and evidence limits

A missing resource extension does not prevent discussing a noun. Missing flow direction is unresolved prose, not an inferred edge. Suggest an experiment without running it.

This release inventories literal controls and formula text; it does not evaluate formulas, resolve units, draw directional flow graphs, or execute simulations. Flow direction stays in rule prose. At most one accepted resource extension per noun is a source invariant to inspect manually here.

## Fixture application

Energy is a noun/resource; initial-energy and push-cost are controls; crate-pushing owns spending behavior. Three required pushes with initial energy 2 raises a conditional feasibility question, not an executed result.
