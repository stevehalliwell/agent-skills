# Website art direction

Create decision-ready visual-direction brief from supplied evidence.

## Trigger clarification

Use for deliberate website visual-expression direction before implementation. If user needs messaging/positioning, full identity work, or code changes instead, route to the appropriate workflow.

## Workflow

1. Frame decision. State site, pages, audience, decision to make, constraints, and implementation horizon. Ask for available live/staging URLs, core pages, positioning/audience material, competitor set, visual references, and selection criteria. Done when scope and decision owner are explicit.
2. Inventory evidence. Review supplied inputs. Record missing evidence and resulting limits. Treat external claims as unknown unless evidence is supplied or user explicitly requests cited research. Done when input confidence is clear.
3. Audit current state. Separate observations from hypotheses. Assess typography, color, spacing, imagery, hierarchy, interaction cues, consistency, and accessibility-relevant legibility against stated audience and goals. Done when audit identifies constraints and opportunities without prescribing direction.
4. Develop directions. Produce 2–3 genuinely distinct visual directions. For each, state concept, audience fit, visual system, risks, and implementation implications for typography, color, spacing, imagery, and hierarchy. Do not treat competitors as assumed direction. Done when each option is comparable.
5. Compare and recommend. Compare directions against user selection criteria, evidence, delivery cost, maintainability, and risk. Label recommendation separately from observations and hypotheses. Done when user can understand trade-offs.
6. Stop for approval. Ask user to select, combine, or reject directions before any redesign implementation. On approval, translate chosen direction into reusable implementation principles. Done when direction remains user-owned.

## Output shape

```text
Website art direction: <site or project>

Scope and evidence limits:
- <pages, audience, inputs, gaps>

Current-state audit:
- Observations: <...>
- Design hypotheses: <...>

Directions:
1. <name> — <concept, visual system, audience fit, trade-offs>
2. <name> — <concept, visual system, audience fit, trade-offs>
3. <optional name> — <concept, visual system, audience fit, trade-offs>

Comparison and recommendation:
- <criteria, evidence, recommendation>

Implementation principles:
- Typography: <...>
- Color: <...>
- Spacing: <...>
- Imagery: <...>
- Hierarchy: <...>

Need from you:
- Choose, combine, or reject direction before implementation.
```

## Rules

- Work from supplied evidence in any repository; state limits rather than inventing site facts.
- Keep observations, design hypotheses, and recommendations visibly separate.
- Competitor patterns are benchmarks for audience fit, not direction defaults.
- Do not perform redesign, browser implementation, brand identity, or marketing-positioning work in this skill.
- Do not start external research automatically or make uncited factual claims.
